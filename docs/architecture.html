Factory Inventory Management System

A demo full-stack inventory platform: a Vue 3 single-page application backed by a Python FastAPI service that serves in-memory mock data loaded from JSON files. No database.

Vue 3.4 · Composition API Vite 5 · port 3000 FastAPI · port 8001 Pydantic validation In-memory JSON data i18n · EN / JA

Data Flow — A Filter Change, End to End

1
User selects a filter
FilterBar.vue writes to a ref in the useFilters composable. Because the refs live at module scope, every view sees the change.
2
View reloads
The active view watches filter state, calls getCurrentFilters(), and re-invokes its loader with loading / error states.
3
Request is built
api.js converts the filter object into query params, omitting anything set to 'all', and issues the axios GET.
4
Server filters in memory
FastAPI applies apply_filters() then filter_by_month() over the in-memory lists, building new lists rather than mutating the originals.
5
Validate and render
Pydantic validates the response against the declared model; the view stores raw rows in refs and derives all totals through computed properties.

The consistent split: raw server rows live in ref() (allOrders, inventoryItems), while every aggregate, chart series, and KPI is a computed() derived from them. Filtering happens server-side; presentation math happens client-side.

Note the naming seam: the UI concept is Location on the client and warehouse on the wire — getCurrentFilters() is the single place that translation happens. Quarters are expanded to their three member months via the QUARTER_MAP constant in main.py. Inventory has no time dimension, so /api/inventory accepts only warehouse and category.

Observations

Client calls endpoints the server does not implement

api.js defines six methods with no matching route in main.py. Any UI path that reaches them will fail with a 404:

  • Tasks — getTasks, createTask, deleteTask, toggleTask target /api/tasks. The task list currently rendered in the UI is hardcoded in the useAuth composable, not fetched.
  • Purchase orders — createPurchaseOrder (POST) and getPurchaseOrderByBacklogItem (GET) target /api/purchase-orders. The server defines a CreatePurchaseOrderRequest model for exactly this, but never binds it to a route, and purchase_orders.json is empty — so has_purchase_order is false for every backlog item.

Two quarter implementations

filter_by_month() uses the QUARTER_MAP lookup, while /api/reports/quarterly re-derives the same quarter boundaries with an inline if/elif chain. Both hardcode 2025, so data from any other year silently drops out of quarterly reports.

Demo-grade security posture

CORS is wide open (allow_origins=["*"]), there is no authentication — useAuth returns a hardcoded user with isAuthenticated permanently true — and no rate limiting. Documented as intentional for local demo use.
